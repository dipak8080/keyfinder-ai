# ---------- AUDIO TO SHEET MUSIC (/audio-to-sheet) ----------
# The sheet/ package's pipeline: transcription -> notation -> engrave.
# Modest footprint (~60-80MB total, mostly music21), nothing like the
# torch/essentia layers.
#
#   music21     MIDI -> MusicXML: quantise to the detected tempo grid,
#               insert key/time-sig, split piano into two staves.
#   verovio     MusicXML -> SVG/PDF engraving. Bundles its own music
#               fonts in the wheel, so no font package is needed for the
#               NOTATION itself.
#   cairosvg    per-page SVG -> PDF. Uses the libcairo2 already present on
#               this image via libcairo2-dev (installed for bgutil's
#               canvas build) - NO new system dependency.
#   pypdf       merge the per-page PDFs into one document.
#   pretty_midi MIDI parsing + note-count summary in the sheet pipeline.
#
# pretty_midi is left with a >= floor rather than a hard pin: it is a
# small pure-Python package and a hard == here risks a resolution
# conflict on a no-cache build if anything else ever constrains it.

verovio==5.6.0

pypdf==6.1.1

# ---------- INSTALLED 2026-09-09: yt-dlp browser impersonation ----------
# curl-cffi (the [curl-cffi] extra on yt-dlp above) supplies TLS/JA3
# impersonation. It was deliberately left out until now, with the note
# below kept as the record of why it went in.
#
# The predicted day arrived. Production log, job 6b6ac216, TikTok:
#     WARNING: [TikTok] The extractor is attempting impersonation, but
#     no impersonate target is available
#     ERROR: Postprocessing: WARNING: unable to obtain file audio codec
#     with ffprobe
# i.e. the extractor asked to impersonate, had no target, fell back to a
# plain request, and TikTok returned something that was not real audio -
# ffprobe then failed on the postprocessing step. Not yet a full outage
# (10 completes against 2 kind=unknown failures in the same 24h), which
# is exactly the shape the old note predicted: TikTok has no client
# ladder to fall through, so its tightening shows up as outright
# failures rather than degraded retries.
#
# YouTube does NOT need this - it has the client ladder (see
# CLIENT_LADDER_* in youtube.py), so impersonation is only a
# nice-to-have there.
#
# WATCH AFTER DEPLOY: curl-cffi ships compiled binaries and replaces
# yt-dlp's request handler for impersonated requests, so YouTube
# extraction is the thing to verify, not just TikTok. Verify targets are
# actually available with:
#     docker exec audioforges-api yt-dlp --list-impersonate-targets
# Rollback: yt-dlp[default,curl-cffi]==2026.07.04 (TikTok is broken on it).
